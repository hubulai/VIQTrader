## 一、产品定位与设计基线

| 维度 | 已确认决策 |
|---|---|
| 使用者 | 个人自用，单用户，不对外开放 |
| 投资风格 | 中长线投资 + 波段，核心为原教旨主义价值投资 |
| 模式结构 | 两套完全独立轨道：价值轨（value）/ 波段轨（swing） |
| 共享边界 | 数据层、执行网关、账本引擎、Web 控制台 |
| 独立边界 | 选股逻辑、决策依据、风控规则、回测方式、账本配额 |
| 资金分账 | 一个券商账户 → 两个逻辑子账本，分别记账 |
| 决策机制 | 投委会式交叉验证（估值 Agent + 反方 Agent） |
| 决策介入度 | 平台只产出研究材料，买卖由人最终拍板 |
| 市场范围 | 主投 A股；港股仅限港股通标的 |
| 交易闭环 | v1 仅模拟盘，不碰实盘（架构预留实盘） |
| 技术栈 | Python 全栈 + DuckDB + 本地 Windows + Web 控制台 |

### 核心设计主张

1. **LLM 与确定性引擎严格分离**：需要推理的工作（筛选判断、估值、复盘解读、唱反调）交给 LLM Agent；回测、风控规则执行、订单撮合、账本记账必须是纯代码，确定性、可回放。
2. **风控独立且先于交易**：风控不隶属选股或策略流程，任何意图交易必须先过规则引擎。
3. **研究深度优先于执行效率**：平台价值集中在研究与估值，回测是验证工具而非核心。

### 投资哲学基线（价值轨，巴菲特派）

1. **股权思维**：买股票 = 买企业的一部分所有权，收益来自企业创造的价值（盈利 + 分红），不来自接盘者。
2. **估值是带假设的区间**：内在价值输出 bull/base/bear 三档 + 全部假设，假设质量比结论重要。
3. **安全边际是唯一买入闸门**：质量优先排序，便宜是闸门不是排序键；估值越不确定，要求折价越深。
4. **能力圈是负面清单**：行业白/黑名单进配置（见第八节），圈外标的一票否决。
5. **卖出只有三个理由**：逻辑证伪、价格远超价值、发现明显更好的标的。**下跌从来不是卖出理由**。
6. **换手率是纪律指标**：价值轨年换手率异常升高 = 风格漂移告警，平台要约束"管不住手"。

### 3.5 文档与外部观点表（券商研报/行业资料）

**document** — 文档元数据（本地 PDF 入库：文件路径、内容 hash 去重、类型[个股研报/行业研报/其他]、关联标的/行业、机构、日期、解析状态）
**document_analysis** — 研报 LLM 解析结果（结构化 JSON：摘要、核心假设、盈利预测、评级与目标价、风险点）——入库时解析一次，之后 Agent 引用结构化结果，不重复读原文
**analyst_forecast** — 结构化盈利预测（机构、日期、标的、财年、预测净利润/EPS、目标价）：① 取中位数得**市场一致预期**；② 预测 vs 实际兑现回填 `outcome_label`，形成**券商预测准确率追踪**

> 治理红线：研报内容一律标注为**外部观点**，与原始财务数据严格区分；Agent 输出引用研报时必须注明来源机构与日期。卖方研报系统性乐观，反方 Agent 须被告知此偏差并将其作为重点攻击面。

## 四、Agent 输入输出契约

所有 Agent 输出均为**结构化 JSON**，且必须附**数据引用**（不允许无据推断）。Agent 不直接下单，只产出材料。

所有 Agent 的 prompt 统一注入两类学习上下文（见第十一节）：① 从 `case_library` 检索的 top-K 相似历史案例（含结局）；② 该 Agent 自己的近期评分卡摘要（如"过去 10 次估值平均高估增长率 15%"），实现自我纠偏。

### 4.1 价值轨

**① 价值初筛 Agent**

- 输入：`fact_valuation`（当期）、`fact_financial`（近 8 季）、`dim_stock`、筛选参数（阈值配置）
- 工作：排除法——**第 0 步先过能力圈**（行业白/黑名单一票否决）；再剔除高负债、连续亏损、现金流为负、无分红能力的标的；**质量优先排序**（ROIC 持续性、毛利率稳定性、自由现金流转化率在前），便宜（低估值）作为买入闸门而非排序键
- 输出：

```json
{
  "as_of": "2026-10-15",
  "candidates": [
    {
      "code": "600xxx",
      "market": "SH",
      "hit_rules": ["ROE>12%连续3年", "PE_TTM<12", "股息率>4%"],
      "metrics": {"roe_3y": 0.15, "pe_ttm": 9.8, "dv_ratio": 0.045, "debt_ratio": 0.42},
      "excluded_flags": [],
      "screen_score": 82
    }
  ],
  "data_refs": ["fact_financial@2026-06-30", "fact_valuation@2026-10-14"]
}
```

**② 深度估值 Agent（核心）**

- 输入：标的财务全历史、`fact_valuation` 历史分位、`fact_dividend`、`fact_disclosure` 摘要、同行业对比组、券商盈利预测与研报核心假设（`analyst_forecast` + `document_analysis`，标注为外部观点）
- 工作：内在价值区间估算（DCF + 相对估值交叉验证，DCF 业绩假设须与券商一致预期对照）、护城河评估、安全边际计算；**必须输出"我的假设 vs 市场一致预期的差异"（variant perception）——超额收益的来源正是这个差异点**
- 输出：

```json
{
  "code": "600xxx",
  "intrinsic_value_range": [28.5, 34.0],
  "current_price": 19.2,
  "margin_of_safety": 0.32,
  "methods": [
    {"name": "DCF", "value": 31.0, "assumptions": {"wacc": 0.09, "terminal_growth": 0.025, "fcf_growth_5y": [0.06, 0.05, 0.04, 0.03, 0.03]}},
    {"name": "相对估值", "value": 30.2, "peer_set": ["000xxx", "601xxx"], "target_multiple": 13.0}
  ],
  "moat_rating": "strong",
  "moat_evidence": ["市占率 35% 且稳定", "毛利率高于同业 8pt"],
  "key_risks": ["地产链需求下滑", "应收账款周转下降"],
  "confidence": 0.72,
  "data_refs": ["fact_financial@2024-12-31", "fact_dividend@2026-07-01"]
}
```

> 强制要求：`assumptions` 必须完整列出，供反方 Agent 逐条攻击。

**③ 反方 Agent（投委会）**

- 输入：估值 Agent 的**完整输出**（尤其 assumptions 与 moat_evidence）+ 相关研报（被告知卖方系统性乐观偏差）
- 工作：逐条攻击假设、找财务雷点、验证护城河是否被高估、检查是否"价值陷阱"、**重点攻击"估值方与研报共同乐观的假设"**
- 输出：

```json
{
  "code": "600xxx",
  "rebuttals": [
    {"target": "assumptions.fcf_growth_5y[0]=0.06", "attack": "过去 3 年 FCF 复合增速仅 1.2%，假设过于乐观", "severity": "high"},
    {"target": "moat_evidence", "attack": "市占率稳定但单价持续下滑，护城河可能正在收窄", "severity": "medium"}
  ],
  "fatal_issues": ["经营现金流连续两季低于净利，存在利润质量疑问"],
  "verdict": "需补充数据后再判断",
  "needs_data": ["近 3 年应收账款账龄结构", "主要客户集中度"]
}
```

### 4.2 波段轨

**④ 波段选股 Agent**：输入量价、资金流、题材；输出候选 + 信号类型 + 进出场参考位（不预测，只描述形态与风险）。

**⑤ 信号解读 Agent**：把量化信号翻译成人话，标注该信号的胜率历史与失效条件。

### 4.3 共用

**⑥ 复盘跟踪 Agent**

- 输入：持仓列表、期间财报、期间公告、`thesis`（原始买入逻辑）、**Brinson 归因结果**（`attribution` 模块先算）、当时的券商预测（`analyst_forecast`，对照预测 vs 实际兑现）
- 工作：分两步——**定量层**（确定性代码）：Brinson BHB 模型把超额收益拆成行业配置效应 / 个股选择效应 / 交互效应，先回答"收益来自配置还是选股"；**定性层**（LLM）：结合财报与公告判断"当初买入的逻辑是否还成立"，并解读归因结果的原因
- 输出：

```json
{
  "position_id": "pos_001",
  "thesis_status": "partially_broken",
  "changes": ["毛利率连续两季下滑 -3pt", "新任管理层战略转向"],
  "suggested_action": "reduce",
  "reasoning": "核心逻辑（成本优势）仍在，但成长逻辑已破，建议降仓不清仓"
}
```

> **落地口径（P4.6，2026-10-17）**：复盘拆为三个相互隔离的契约——**归因解读**（组合级：summary / allocation_comment / selection_comment / key_findings[] / data_refs[]，只解读不重算数字）；**thesis 复核**（持仓级，字段同上示意；硬约束：`falsified` 必须配 `exit`；`changes` 只收区间内事实陈述，价格下跌不构成证伪；无变化填 ["无显著变化"]；输入 period_facts=行情区间+ann_date 落在区间的财报+公告，point-in-time 装配）；**pipeline** 三段失败隔离（归因 unavailable、风控 empty、无 active thesis 跳过均为正常结果，单仓异常不连坐）。Brinson 口径（基准/现金段/新建仓等）见文末变更记录 2026-10-17 条目。

**⑦ 研报解析 Agent**（入库管线用，非投委会成员）

- 输入：本地 PDF 研报/行业资料（人工下载后丢入指定文件夹）
- 工作：提取摘要、核心假设、盈利预测（结构化进 `analyst_forecast`）、评级与目标价、风险点
- 输出：结构化 JSON 存 `document_analysis`；**一份研报只解析一次**，之后估值/反方/复盘/行业判断全部复用解析结果，不重复读原文（成本控制）

**⑧ 风控解读 Agent**：把风控引擎触发的规则事件翻译成可读提示与建议动作。

> **落地口径（P4.6，2026-10-17）**：输出 `overall_risk ∈ normal/warning/critical` + `items[]`（每条 `rule_key` / `interpretation` / `suggested_action`）；区间无风控事件为空数据 fail-fast，不调用 LLM（空事件不解读）；事件时间按 `CAST(event_ts AS DATE)` 落区间过滤。

## 五、两轨执行流程

### 5.1 价值轨（低频，财报季驱动）

```
价值初筛 Agent
   → 深度估值 Agent
      → 反方 Agent（投委会交叉验证）
         → 安全边际闸门（确定性规则：折价率是否达标）
            → 人工确认（你拍板）
               → 组合仓位引擎（配额、集中度）
                  → 模拟撮合下单
                     → 存档 thesis（买入逻辑）
                        → 财报期：复盘跟踪 Agent
                           → 卖出判断（高估兑现 / 逻辑破坏 / 更优机会）
```

### 5.1.5 狩猎清单工作流（价值轨前置，研究先行）

巴菲特派的日常状态是"功课已做完、价格还没到"，而不是"发现机会才研究"：

```
心仪标的 → 提前跑投委会（估值 + 反方）→ 结论与假设存入 watchlist（含安全边际买入价）
   → 每日引擎只盯一件事：价格是否跌穿安全边际线
      → 跌穿即触发 WARN 告警（附存档研究摘要）
         → 人工确认 → 模拟撮合（研究已存档，无需重跑）
```

规则：
- 存档研究**有保质期**（`review_expiry_days`，默认 90 天），过期标记 expired，需重新投委会复核后才恢复 ready。
- 期间有新财报/重大公告 → 自动触发复盘 Agent 检查 thesis，必要时提前过期。
- 已持仓标的不进狩猎清单；同标的从 watchlist 成交后自动转入 `position` + `thesis`。

### 5.2 波段轨（日/周线驱动）

```
波段选股 Agent
   → 信号解读 Agent
      → 风控规则（止损位、仓位、最大持仓数）
         → 人工确认
            → 模拟撮合下单
               → 出场规则（止盈/止损/持有期上限）
```

两轨**共享**：数据层、执行网关、账本引擎、Web 控制台。
两轨**互不干扰**：任一轨的操作不影响另一轨的持仓与配额。

### 5.2.1 波段初筛多策略架构（2026-10-17 新增，P4.5.1 落地）

波段不止一种打法，初筛层设计为**多策略可插拔**（策略界面可选、阈值参数可配、历史区间可回测）：

- **策略协议**：`ScreenStrategy`（strategy_id / 展示名 / 描述 / `params_schema()` / `compute()`）。compute 为零 DB 纯函数：输入升序日 K + 已解析参数，输出形态特征（patterns + score + 特征快照），样本不足返回 None。
- **参数即界面契约**：每个参数以 `ParamSpec` 声明类型、默认值、取值范围与中文说明；控制台经 `list_strategies()` 直接渲染「策略选择 + 参数表单」——后端契约先行，P6 消费，新策略无需改前端代码。
- **注册表**：`strategies/registry.py` 静态注册，新策略注册一行即全链路（screen / pipeline / backtest / 控制台）可用；`swing_track.active_strategy` 决定当前启用策略。
- **参数三层合并**：schema 默认值 ← YAML `swing_track.strategies.<id>` 节 ← 调用方覆盖（CLI `--param` / 回测网格）；未知键、越界值 fail-fast，防配置手滑静默失效。
- **历史重放**：`screen_candidates(as_of_date=T)` 在 SQL 层按 T 截断取数，逐日 as-of 重放无前视，是初筛信号回测的统一入口（见第九节）。
- 首发策略 `trend_momentum`：放量突破 / 回踩企稳 / 底部金叉三形态并集打分 + 多头排列趋势加分（7 参数全外置）；`swing_signal` 落库带 `strategy_id` 列（迁移 0006），审计可回溯信号出自哪套策略。

### 5.3 波段轨策略生命周期（借鉴课程平台设计）

波段策略不直接上线跑量，按 5 阶段 KPI 驱动自动迁移，并联动资金配额：

| 阶段 | 含义 | 晋级 KPI（阈值全部进 config） | 资金 |
|---|---|---|---|
| INCUBATING 孵化 | 仅回测验证 | Walk-Forward IS/OOS > 0.7 | 0 |
| PAPER 纸交易 | 模拟盘跑 1 个月 | 累计收益 > 0 且最大回撤 < 5% | 0（虚拟） |
| PROBATION 试用 | 小资金模拟配额 | 1 个月 Sharpe > 0.5 | 波段子账本的 5~10% |
| PRODUCTION 主力 | 稳定运行 | 滚动 30 日 Sharpe > 1.0 且回撤 < 15% | 波段子账本的 30~50% |
| RETIRED 退役 | 自动下架 | 30 日 Sharpe < 0.3 持续 2 周，或单日亏损 > 3% 立即退役 | 0（清仓） |

> 价值轨**不适用**此机制：Sharpe 类短期 KPI 对长期持有无意义，价值轨的"退役"由 thesis 证伪（复盘 Agent）决定。

### 港股通专项约束（必须落在数据层与账本层）

1. **名单动态跟踪**：调出后只能卖不能买 → 风控引擎强制拦截对 `is_hk_connect=False` 标的的买入意图。
2. **红利税**：H股 20%，红筹/非H股可能 28% → 估值模型的股息率必须按**税后**计算。
3. **汇兑**：人民币结算 → 账本双口径（原币 + 人民币），单独跟踪汇兑损益。
4. **交易日交集**：仅 A股与港股**同时开市**的交易日可交易。
5. **不可参与** IPO / 配售 / 供股。
6. **T+0 回转交易**：与 A股 T+1 不同，波段轨规则需分开处理。

> 注：港股通标的已由交易所按市值与流动性预筛，**老千股/价值陷阱筛查可降级**（不做专项，但仍在反方 Agent 中作为检查项之一）。

## 七、风控设计（两轨规则不同）

> **三阶段规则管线（2026-10-15 新增，详见《A股交易规则引擎与双轨账本详细设计》v1.1）**：任何订单意图按固定顺序过三层规则——Phase 1 市场规则（T+1/交易日/停牌/涨跌停/手数/港股通名单，纯市场机制）→ Phase 2 账户规则（资金充足/可用持仓/模式隔离/双轨配额）→ Phase 3 风控规则（本节 7.1/7.2 两轨规则集）。任一规则拒绝即终止并留痕。TradingRule Protocol 可插拔，参数全部走 YAML。

> **已确认决策（2026-10-15）**：双轨配额（80/20）为**软限制**——超限不阻断交易，产生 WARN 级 risk_event 走告警，最终拍板权在用户；Intent 不冻结资金，FILLED 才扣款，`execute_fill` 扣款前重检资金兜底（不足则 REJECTED: `INSUFFICIENT_CASH_AT_FILL`），账本永不出现负现金。

### 7.1 价值轨（**基本面止损**，非价格止损）

> 核心边界：价值止损只在**买入逻辑被证伪**时触发，绝不因价格下跌而止损。好公司跌了反而是加仓机会。

| 规则 | 档位 | 说明 |
|---|---|---|
| 安全边际闸门 | 买入前 | 折价率低于阈值（如 < 30%）则拒绝买入 |
| 单票仓位上限 | 买入前 | 单标的占子账本比例上限 |
| 行业集中度 | 买入前 | 单一行业敞口上限 |
| **基本面硬止损** | 持有中 | 财务造假/ST 预警/审计意见非标 → **直接触发卖出**（公告事件驱动，`fact_disclosure` + LLM 判断） |
| **基本面软止损** | 持有中 | ROE 连续 N 季低于阈值、经营现金流连续转负、净利润连续下滑 → 触发复盘跟踪 Agent 评估，由人确认是否卖出 |
| 港股通名单拦截 | 全流程 | 调出标的禁止买入 |

### 7.2 波段轨（传统风控）

| 规则 | 说明 |
|---|---|
| 止损线 | 固定百分比或 ATR 倍数（**价格止损**） |
| 单票仓位上限 | |
| 组合回撤上限 | 触发后暂停开新仓 |
| 最大持仓数 | |
| 持有期上限 | 超期未达标强制退出 |

> 两轨止损的本质差异：价值轨止损 = 逻辑证伪；波段轨止损 = 价格触线。这是两条独立规则集存在的根本理由。

### 7.3 告警分级路由（借鉴课程平台设计）

风控事件、Agent 结论、系统异常统一走 `alerting` 模块，按级别分渠道，解决告警疲劳：

| 级别 | 场景 | 渠道 |
|---|---|---|
| INFO | 信号触发、仓位变化、财报季批量复盘结论 | 控制台 + 聚合推送（30 分钟一批） |
| WARN | 风控否决、软止损触发、数据缺口 | 控制台 + 实时推送 |
| CRITICAL | 硬止损触发、组合回撤触上限、异常订单 | 全渠道 + @人 |
| FATAL | 数据层失效、账本不一致、引擎崩溃 | 全渠道 + 多次重试，暂停交易引擎 |

## 八、参数配置体系（全部阈值可配置，不硬编码）

### 8.1 设计原则

1. **所有阈值外置**：资金配额、风控阈值、选股筛选条件、回测成本假设全部写在 YAML 配置里，改参数不动代码。
2. **参数版本化（关键）**：每次风控判断、回测运行、Agent 决策都记录当时生效的**参数快照哈希**。调参之后，历史事件仍能按当时的规则复盘，不会出现"用今天的规则误解昨天的决策"。
3. **分层配置**：`default.yaml`（平台默认值）→ `user.yaml`（你的覆盖值），后者优先级高；敏感项（API token）走 `.env`，不进版本库。
4. **热加载**：控制台修改参数后立即生效（下次规则评估用新值），但**不影响已存档的历史快照**。

## 九、回测设计

**统一事件驱动骨架**——同一个策略接口在回测、模拟盘、未来实盘三种环境下运行，环境差异全部封装在数据适配器与执行网关中（环境同构）。

| 轨 | 回测形态 | 输出指标 |
|---|---|---|
| 价值轨 | 持有期分析 + 定期再平衡 | 年化、IRR、相对指数超额、最大回撤、持有期分布 |
| 波段轨 | 信号回测（成交口径） | 胜率、盈亏比、年化、换手率、单笔最大亏损 |

**初筛信号回测（2026-10-17 新增，P4.5.1）**：上表成交口径统计已成交 round-trip 的胜率/盈亏比（`engine/backtest/swing.py`）；初筛信号回测（`agents/swing/backtest.py`）回答更上游的问题——「这套初筛策略 + 参数组合在历史区间选出的信号质量如何」。**零 LLM、不落库**（不污染 `swing_signal` 建议层），经 `screen_candidates(as_of_date=T)` 逐日 as-of 重放全市场初筛，双口径评估：① 固定持有 5/10/20 交易日收益（数据不足记 None 统计剔除）；② ATR 触位出场（回测无 LLM 参考位，以 stop=entry−2×ATR14 / target=entry+3×ATR14 推算，同日触及两侧保守按止损先走，max_holding_days 内未触及按 timeout 收盘出场）。`--grid k=v1,v2` 笛卡尔积参数网格逐组合独立重放/评估/汇总，产出明细+汇总两份 CSV（utf-8-sig）与控制台汇总表，供参数调优与新策略评审。

**成本模型**
- A股：佣金 + 印花税（卖出 0.05%）+ 过户费
- 港股通：印花税 0.1%（双边）+ 交易费 + 汇兑成本 + 红利税

**前视偏差处理（硬约束）**
- 免费/普通数据源的财报多为"修正后"版本，缺少 point-in-time 历史版本。
- v1 策略：以 `fact_financial.ann_date`（披露日）作为可见时点近似。
- 所有回测结果**必须标注"精度受限"**，不得当作可信结论使用。
- **代码级防线（2026-10-15 新增）**：策略代码入回测前过 AST 静态 linter（借鉴 web3-quant-sandbox `dsl/lookahead.py`），检测 `shift(-N)`、未来索引等模式；P4 LLM 生成策略时强制启用；误报支持人工豁免注释并留痕。注意：linter 只管代码级偏差，数据级偏差（前复权价、幸存者偏差）靠数据层规范（存原始价 + 复权因子，point-in-time 计算）。

**订单意图协议（2026-10-15 新增，借鉴 web3-quant-sandbox）**：策略层与执行层之间以不可变 `OrderIntent` 为唯一契约（Python 层 Decimal 精度，落库转 DOUBLE），回测/模拟/未来实盘三环境复用同一套 Intent + 规则引擎 + 账本引擎，差异仅封装在数据适配器与执行网关。详见《A股交易规则引擎与双轨账本详细设计》v1.1。

**Walk-Forward 过拟合检测（波段轨标配，借鉴课程平台设计）**
- 滚动窗口：用过去 N 个月训练最优参数 → 用接下来 M 个月样本外评估 → 滚动前进。
- 输出每个窗口的 IS/OOS Sharpe 比例与过拟合分数 = (IS − OOS) / IS。
- IS/OOS < 0.7 的策略**禁止进入** PAPER 阶段（与 5.3 生命周期门禁联动）。
- 价值轨回测不做参数寻优（买入条件是财务规则而非拟合参数），可豁免，但仍按披露日近似处理。

## 十一、自我学习机制

### 11.1 设计红线

1. **学习 = 反馈闭环，不是自动调参**：平台只提议、不自动应用。所有学习产出（参数建议、新规则、prompt 改进）必须经人工审批后生效——短期噪声污染长期逻辑是价值投资的死穴。
2. **分层学习，速度不同**：参数层（波段策略，周/月级，走 Walk-Forward + 生命周期）→ Agent 层（季度级，评分卡驱动 prompt 改进）→ 认知层（年级，thesis 复盘，平台只做记录与对照）。
3. **样本量陷阱**：个人平台年交易几十笔，统计上不支撑频率派自动优化。学习以**定性案例积累**为主（LLM 擅长），不以统计回归为主。

### 11.2 四个机制

| 机制 | 做法 | 模块/表 |
|---|---|---|
| **结果标签化** | 每个决策（初筛/估值/投委会/thesis/交易）在 1月/6月/1年/3年 四时点自动回填实际结果：超额收益、估值误差、逻辑兑现与否 | `learning` 定时任务 → `outcome_label` |
| **Agent 评分卡** | 按 Agent × 决策类型滚动统计：估值误差分布、反方致命问题命中率/误报率、初筛候选 6 个月超额；评分卡摘要注入回该 Agent 的 prompt 自我纠偏 | `agent_scorecard` |
| **错误案例库** | 失败决策做尸检（post-mortem），按行业/thesis类型/失败模式打标签入库；Agent 遇相似情境时检索 top-K 案例 few-shot 注入——"上次在地产链犯过同样的错" | `case_library` |
| **季度元复盘** | 元复盘 Agent 每季度横切全部结果，产出学习提案（调参/淘汰某类 thesis/强化某条筛选规则）；提案走控制台审批，批准后生效并存 `config_snapshot` 新版本，支持参数版本长期 A/B 对照 | `learning/meta_review` |

### 11.3 防护

- **递归污染**：案例库只存"原始数据标签 + 尸检结论"，不存 Agent 自我解读；学习提案必须经反方 Agent 审查后再上人审。
- **奖励劫持**：评分卡多维正交（准确率/误差分布/逻辑兑现率分开记），不优化单一收益指标；终裁权在人。
- **反馈周期匹配**：价值轨 thesis 的标签回填以 1年/3年 为主窗口，1个月标签仅供参考，绝不触发任何自动动作。

## 十二、变更安全与回归保障

### 12.1 核心机制：确定性回放

平台"LLM 与确定性引擎分离 + 全量决策留痕"的设计天然构成回归保障地基：引擎层是纯函数，历史运行完整可回放。**任何引擎代码修改后，重放过去 90 天真实数据，diff 新旧决策输出，生成"决策 diff 报告"人工审阅后再上线**——比断言测试覆盖更全，因为回放覆盖的是真实发生过的所有场景。

### 12.2 防护体系

| 层 | 机制 | 防什么 |
|---|---|---|
| 单向依赖 | 数据→引擎→Agent→编排→Web，下层永不 import 上层（lint 强制） | 改 Web 碰引擎 |
| 契约校验 | 数据适配器 Protocol 一致性测试；Agent 输出 JSON Schema 强校验，不合格拒绝入库 | 模块内部改动外泄 |
| LLM 盒带 | 测试录制真实 LLM 响应重放（cassette），可重复、零成本、离线 | Agent 不确定性致测试 flaky |
| 黄金数据集 | 冻结真实数据快照，引擎全量跑，输出与基准 diff | 引擎逻辑回归 |
| 回放验证 | 引擎改动后重放历史，决策 diff 报告人审 | 改一处坏一片 |
| 双版本留痕 | 记录表含 `config_hash` + `code_version`（git commit），任何历史决策可还原"当时代码 + 当时参数" | 灵异 bug 无法复现 |

### 12.3 两条纪律

1. **prompt 即代码**：prompt 存 git 版本化、改动需评审；新 prompt 先影子运行（与旧版并行、对比评分卡），达标再替换——与波段策略生命周期同一思想。
2. **数据库迁移只增不改**：版本化迁移脚本，只加表加列，不改旧列语义，老数据永远可读。
