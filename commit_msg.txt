4.1 LLM 通道（src/viqtrader/agents/llm/，零新增依赖）：
- base.py：Message / LLMResponse（content/model/token_in/token_out/cost_cny/latency_ms/
  status）/ LLMProvider Protocol（统一 complete(messages, model, **params)）/ LLMError
- pricing.py：读 config llm.pricing（CNY / 1K token）算 cost_cny，全程 Decimal；
  精度保留 6 位小数——单次调用成本常低至「分的百分之一以下」（如 3K token≈0.003 元），
  按分舍入会一律归零、失去核算意义；未配置单价的模型返回 None（留空不猜，避免审计失真）
- openai_compat.py：标准库 urllib POST {base_url}/chat/completions，OpenAI 兼容协议
  （DeepSeek/Qwen/GLM/Kimi 通用）；密钥经 api_key_from_env 从 .env 读，
  仅出现在请求头、绝不进盒带与快照；HTTP 传输可注入（http_post），
  测试离线验证请求构造与响应解析，无网络无密钥
- fake.py：FakeProvider 预设/脚本化返回 + 记录调用，测试零网络零成本
- cassette.py：CassetteProvider 包装真实 provider，录制落盘 / 重放查表；
  fingerprint=sha256(规范化 {model, messages, 显式参数})，排除 None 与凭据；
  重放未命中 fail-fast 抛 CassetteMissError，杜绝测试偷发真实请求；
  布局 <cassette_dir>/<agent>/<case>.json
- runs.py：write_agent_run 落 agent_run 一行，字段严格对齐 0002 schema；
  审计红线 config_hash + code_version 必填；cost_cny Decimal→float 入库

4.2 Agent 输出契约（src/viqtrader/agents/contracts/）：
- base.py：ValidationResult（ok/errors/payload/parsed）+ AgentContract 协议 +
  BaseContract（PEP695 泛型骨架，子类只实现 parse）；run_contract 不合格
  带错误提示重试 1 次 → 仍不合格标 DEGRADED；parse_json_response 容忍
  markdown 代码块与前后废话（先整段、再围栏、再首尾花括号兜底）
- valuation.py / dissent.py：深度估值（区间/方法+假设/护城河/安全边际/
  variant_perception/data_refs）与反方（rebuttals 逐条 target+severity/
  fatal_issues/verdict/needs_data）两份 dataclass 样板契约，逐字段校验、
  错误全量收集后 raise ContractError，通过则回填强类型实例
- persist.py：persist_contract_run —— 落 agent_run；仅 SUCCESS 写 agent_output，
  DEGRADED/FAILED 只留 agent_run 痕（不合格结论不得入库）

4.3 Prompt 版本化（src/viqtrader/agents/prompts/）：
- registry.py：PromptRegistry 加载 manifest、取版本化文本；
  string.Template 用 $var 占位，避开 prompt 内 JSON 契约的花括号；
  已发布版本不删（历史 agent_run 的 prompt_version 需可回溯）
- manifest.yaml：name → {version, path}；texts/valuation.v1.md、texts/dissent.v1.md
- version() 产 <name>.vN 注入 agent_run.prompt_version

4.4 投委会 Agent + 编排（src/viqtrader/agents/value/，P4.4）：
- valuation_agent.py：load_valuation_inputs 从 DuckDB 装配输入快照——
  财务按报告期倒序随 ann_date（point-in-time）、最新估值截面含 pe_percentile、
  分红、公告摘要、同业估值对比、研报共识（document+document_analysis 已解析
  结果，标注机构/日期与自身假设严格区分）；run_valuation_agent 渲染
  valuation.v1 → run_contract（重试/DEGRADED 语义继承 4.2）→ persist
  （input_snapshot 存完整装配快照供审计回溯）
- dissent_agent.py：输入估值方完整 JSON 输出 + 研报共识，攻击关键假设与
  估值方/研报共同的乐观偏差
- committee.py：run_committee 编排——估值方 DEGRADED/FAILED → 会话中止
  留痕、不跑反方；反方失败 → 估值结论保留、半程存档；成功 → 双方
  output_id 并列写 committee_session，final_decision/decided_by/decided_at
  留空——最终买卖决策由用户拍板；notes 汇总双方要点（置信度/安全边际/
  攻击条数/致命问题数）
- scripts/run_committee.py：CLI 入口（--code 默认 600519 贵州茅台，可带
  --peer-codes 同业对比）；库中无该标的财务数据时拒绝出结论 exit 2；
  真实 LLM 响应按日归档盒带 tests/fixtures/llm_cassettes/committee/
  <code>_<date>.json，同日重跑命中指纹即离线重放（零成本可复现）
